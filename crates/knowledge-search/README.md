# Knowledge Search

Eligibility, deterministic bounded partitions, file-level reciprocal-rank fusion and disk vectors.
The actual `knowledge-retrieval::KernelAdapter` is the only lexical executor. There is no second schema, trigram engine, numeric/pending grant, model registry or resource pool.

## Actual shared admission

`AccountGrant::reserve(Reservation, Origin)` obtains a real Ready lifetime from `Account::current`; `from_work(Work)` transfers an existing real capability. Funded owners use `Work::split_claim(claim, verified_key, need)` rather than reserving their job twice. Clones retain the SAME lifetime and do not create independently spendable credit. The caller supplies the full concurrent input/projection/query/output envelope before construction. Deadlines/short grants refuse before creating a store. Core must already be started by the native owner.

The facade retains the actual tokenizer/runtime cost once on that same account; Root and generic consumers share it. No duplicate host runtime charge is required.

## Kernel composition

`publish_lexical`, `query_lexical`, `search_lexical` execute through the mature facade and actual Control/Work, not direct independent `Kernel::new` calls. Stable partitions bound encoded inventories at 4 MiB/8000 documents; long inline representations split at UTF-8 boundaries. These are shard-format bounds, not a corpus cap. Exact/regex visit every eligible partition, never lexical candidates only. Equal bytes do not merge source identities. Cross-partition BM25 uses dense file ranks rather than comparing independent scores.

Root's production search wrappers use its existing current-generation planner and this SAME facade. The competing root lexical build is retired; the retained publication hook writes only the actual native reference. Unified method/keyword alternatives preserve ordinary literal and file-navigation semantics and return the original ranking/coordinates for a single method; tags do not become pseudo-body grep matches. The eight original unified controls remain active.

## Disk vectors and remaining composition

`VectorStore` writes little-endian f32 bytes and identity/row locations; eligible rows are chosen before row IO. Its nine original orchestration cases remain, with unchanged assertions. The caller explicitly makes its newly owned fixture root private; the engine no longer chmods unknown existing directories.

The current IO/lifetime slice moves the one actual `Work` out of `AccountGrant` (all clones see it consumed), streams fixed-window float encoding/hash/write accounting instead of assembling a second whole segment, retains funding through affine query results and real independent flock pins, and preserves unknown generation files. A result owns its exact used FD and cost; `into_store` destroys those buffers/readers before reuse. Reopen hashes payloads in bounded windows; a query verifies each eligible row without reading ineligible row bytes. The same prepaid numerical allocator control observes OLD 38,479,318 versus NEW 5,645,652 bytes above live 32 MiB inputs against its unchanged 16 MiB assembly ceiling. This is not physical RSS or embedding quality.

This is still NOT full M4 activation: build inputs and metadata remain resident, full model/provider/normalization identity and generic archive vector IO remain required, as do descriptor-qualified Root publication/recovery/retirement and actual native current-source/Claim/whole-tuple delivery. Root still uses its retained-v1 vector carrier. No second vector/lexical engine, model SDK replacement, native platform or final product claim is made.

The [retrieval adapter](../knowledge-retrieval/README.md#generic-native-generations-and-stored-queries) now provides a compiled generic native-generation query and verified STORED Directory mechanism using the same mature kernel.
Root caller activation, streamed generic publication, full-corpus streaming, funded vector lifetime strengthening and combined generation composition remain required.
Retained snapshots, borrowed labels and partial compatibility declarations cannot waive them.
