## Implementation

Two fixed jobs use Ubuntu 24.04 x86_64 and macOS 15 ARM64, with actual architecture checks.
GitHub's [standard public runner table](https://docs.github.com/en/actions/reference/runners/github-hosted-runners) identifies `macos-15` as ARM64; the workflow also rejects a different observed architecture.
Main pushes use relevant code/build path filters; manual dispatch is available.
The workflow uses read-only repository permission, commit-pinned checkout/artifact actions, standard minimal Rust installation from `mise.toml`, system FFmpeg, and no Docker or model installation.
Each lane permits at most two Cargo build jobs.
No cache or additional dependency installer is introduced.
Package-manager FFmpeg versions are recorded, not misrepresented as a cross-platform codec-output pin.

The single gate entrypoint inventories real libtest cases, including doctests, and compares the complete execution against that inventory.
It uses workspace flags so new members join automatically, while the current root compatibility member remains included.
It rejects an empty inventory, new ignored cases, missing outcomes, failed outcomes, and mismatched case multiplicity.
The existing macOS real-ASR case is the only declared opt-in exclusion.
It does not alter test semantics, apply Cargo filters, or maintain a parallel crate/test registry.
Commands have explicit PASS/FAIL/TIMEOUT observations and bounded process-group cleanup.

Linux produces a compressed CLI artifact after the headless gate.
macOS runs an additional accounted GUI-feature workspace suite, builds the GUI feature, and packages the app with an explicit `--ci-unsigned` option.
This extra feature-configuration suite follows the integrated workspace toolchain owner.
The option requires GitHub Actions CI flags and omits enclosing-app signing, not mandatory ARM64 linker signatures.
The normal no-argument local bundler still signs nested code and verifies the staged and installed app signatures.
Both archives are unpacked and their exact CLI executable is smoke-tested before upload.
No Developer ID, notarization, Gatekeeper, Finder, or visible native-window proof is claimed.

## Necessity And Ablation

One gate entrypoint fills the existing gap in complete-case accounting and declared-ignore enforcement; Cargo remains the test framework.
Removing the accounting check allowed the deliberate empty-inventory stand-in to reach an otherwise successful command path; with accounting enabled, that case fails.
A deliberately sleeping stand-in exercises the process deadline; the admitted timeout path kills/reaps it and reports TIMEOUT.
No registry, runtime plugin layer, or new test framework is added.
The unsigned option is necessary to produce an explicitly labelled CI bundle without changing the local signature gate.
Without the option, the existing bundler applies the local ad-hoc app signature.
