# Native SSH History And Inert Held-File Bundles

## Scope And Compiled Seam

The existing [History seam](../../crates/knowledge-history/README.md) keeps M1's prepare/install/publish signatures and the protected exact proposal-ref transaction. It now implements actual native SSH signing, immutable cryptographic verification, bounded native child ownership, external-observation attribution, and held-file exact-stream bundle verification/object admission. The README is crate Rustdoc and contains a compiled signer/bundle host example for M1/M5/M6.
This is not complete product history acceptance: existing-repository adoption and actual remote/schedule mechanisms remain this activated owner's next work; native macOS/Keychain/GUI prompts and an independent consequential Git/durability review remain required qualification.

## Actual Signing And Attribution

Only explicitly selected public descriptors and native agent sockets enter the signer API. The service's human identity and validated operation/tool/session facts remain separate from agent claims; a distinct selected committer is recorded in the durable recipe. Existing recipes default the additive fields, retaining their original unsigned payload/fingerprint semantics.
System `ssh-keygen` signs actual Git commit payloads, whose standard gpgsig encoding also passes independent native `git verify-commit`. Exact public selection and actual signed bytes are synced before object/ref publication, avoiding a second randomized signature on retry. Missing/locked providers leave retained candidate text and do not make an unsigned commit; completed retry and immutable verification work without that provider.
Actual SSH verification distinguishes valid-known, valid-unknown, invalid and unsigned. A native user chooses public trust; package keys/trailers are not grants. Other signature encodings remain preserved and are not falsely classified as cryptographically invalid by an SSH-only verifier.
The first-use setup is an actual system Ed25519 key generation/load outside home/history/cache, not a product account or a dialog stub. Tests create only disposable 0700 system directories/0600 keys and their own finite native agent/socket. No real user keys, ambient agent, private configuration or Keychain is used. Real interactive/native provider prompts are not claimed by the deterministic proof.
External observation preparation records M1-supplied real stable-observation IDs and `external_unknown`, not a guessed editor or agent authorship. M1 still owns actual quiet-period/stable-file observation and native permission.

## Inert Bundle Binding For M5

`verify_bundle` and `admit_bundle` accept a held regular `File`, exact expected `ContentDigest`, and the existing claim. M5 must first copy its actual VerifiedSource to private owned output and verify that copied exact stream. Paths, hashes and advertised refs are not current-context authority.
The backend bounded-preads without moving the source cursor, verifies actual before/after FD version and SHA-256, and uses the existing native executor for both Git prerequisite/header verification and actual pack unpack/checksum validation in private quarantine. It does not merely trust a successful header inspection.
Object admission redoes those checks and uses native unbundle to admit actual objects only. Neither path activates refs, checks out files, writes home bytes, imports configuration, trusts package signer claims, starts helpers/submodules or contacts a remote. Native M6 context, expected-ref checks and genuine approval remain necessary before any later selected ref publication.
Real controls cover successful native object admission with no public version/ref grant, unchanged held cursor despite a replaced visible pathname, wrong stream digest, native bad pack checksum, missing prerequisites and foreign namespace refusal with no main-object/ref effect.

## Lifetime, Resource And Compatibility Boundary

No queue/account/reservation pool is added. `required_resources` publishes a concurrent envelope for the native host to compose into its same Core P1 claim/prefunded credit. Parent buffers, native group RSS and actual generated storage/artifacts must remain covered by real caller credit; retained output capacity needs its real retained holding, not a completed job flag.
The executor uses bounded nonblocking stdin/stdout/stderr, the earliest original claim deadline, aggregate actual owned-group RSS observations, pre-exec regular-file extent ceilings and finite PID/start-pinned collection. It never substitutes an address-space rlimit or a one-shot RSS observation for collection.
`Error` is Clone rather than Copy because `UnsettledChild` owns the actual unreaped process, pipes, writer descriptor and recognized scratch, including after dropping History/runtime. It is preserved through ordinary error source chains. M1/M5/M6 must retain that owner and causing Core credit, collect it, reconcile actual artifacts, then settle; never stringify it into metadata-only failure/completion. Only the creating process can collect/unlock it.
The owned OS controls prove blocked input cannot defeat the deadline and actual escaped owned I/O keeps the lock/scratch/owner through runtime drop until native EOF/group collection. The isolated CI flock fix remains `3a7d18b`; its deterministic dup2/exec controls and both independent-target counterfactual REDs are preserved. All protected 13 Git assertions/budgets remain unchanged.
Proposal pagination now uses bounded native namespace patterns for an exclusive ASCII cursor, without all-ref output, another branch index, or reliance on newer Git's start-after option.
