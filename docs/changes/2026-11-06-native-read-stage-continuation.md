# Same-claim read-stage continuation

A bounded full-corpus job cannot settle its enclosing job after its first source, or lose
its complete working envelope to global release at every successful M3 stage. The new
`NativeIndexInput::finish_stage` destroys real representation metadata and the actual M3
value, collects native work using the existing foreground collector, then returns the same
processing/source descriptor owner and actual still-live Claim without queue settlement.
M3 and index-metadata loans rejoin that exact original claim only after their payloads die.
Extra input/output staging owners are refused with the actual owning error, not forgotten.
Existing ordinary completion/error/shutdown behavior remains; this is not a publication receipt.

The first stage-return control found a genuine intermediate lifetime mismatch: even after
returning output/metadata loans, the mature reader released its 33-byte input loan globally
before returning its value. That is correct for an independent call, but loses a continuation's
working envelope. `Funding::ClaimStage` uses the SAME native Core split/checkpoint/full key,
not another account, pool or authority. Its successful Credits retain working loans through
returned data; input bytes are already destroyed before that lifetime transfer. Ordinary
Claim/BeforeVerification behavior is unchanged. Existing size/child/group/IO/timeout promises
are unchanged, and no output-changing parser implementation has been introduced.

An actual owner-selected M1 UUID and descriptor supplies real Markdown and real HTML/Japanese.
Each format owns one isolated account, actual source Claim and ALL-free-credit pressure.
Eight real M3/indexed stages preserve that same running claim and zero global availability;
HTML uses the actual freshly built parser-worker/owned collector. Its final job settlement
happens separately, after all stages. Existing paid opaque-page reuse and SDK metadata-scope
controls compose in the same actual native fixture.

Retained intermediate REDs: stage-1/stage-3 returned33 global bytes; stage-2 exposed five
exhaustive compatibility matches, repaired to treat the new lifetime exactly as Claim;
first worker build used a nonexistent binary name and was not evidence. Correct parser-worker
build and deciding Markdown/HTML controls pass. Independent transient-credit and global-finish
ablations actually fail; restored behavior rejoins the real loans without a release/reserve gap.

This establishes read-stage continuation only, not full-corpus execution, aggregate input
identity, lexical/vector tuple publication/recovery/retirement, real WeMM quality, M6 effect
mediation, or native/installed/full-product acceptance. A failed stage still retains its actual
owner; the enclosing generation must not pretend that a failure is complete coverage.
