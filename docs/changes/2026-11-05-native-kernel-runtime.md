# Native Kernel And Authority Integration

## Responsibility

The new `knowledge-retrieval` facade invokes the actual vendored kernel under Core's existing process account. Root `KnowledgeBase` publication and lexical/grep/hybrid/unified search consume it. The old storage publication hook writes a kernel reference instead of constructing a second lexical index; the unused trigram wire field stays empty for compatibility. Metadata and mature vector behavior remain retained adapters, not a new vector engine.

The legacy snapshot is projected into deterministic bounded native kernel shards. Each query uses one retained processing snapshot; independent lexical shard lists are fused as ranks with file deduplication, never compared as raw BM25 scores. The lexical component identity excludes vector-only changes, while the outer validated processing snapshot still owns the complete model/vector tuple. Source hashing/revalidation uses descriptor-relative no-follow opens; changed source bytes or an unavailable actual kernel generation cannot fall back to the old engine.

Consuming compatibility includes the actual root lock, vendor provenance/current source identity, processor source identity (including the opaque worker), feature/target characteristics and the kernel's dictionary identity. Original source digests and derived representation identities remain separate.

## Admission And Lifetimes

Root startup creates/reuses the single Core owner on a private native cache volume. There is no additional account, scheduler or memory pool. Root inventory/snapshot/decode work is admitted before materialization. Actual dictionary/runtime costs, cached snapshots, active readers and frame buffers retain their own costs independently of execution slots.

The M3 phase-two file APIs are imported unchanged. Root transfers their returned text into its snapshot by a real deep copy: first grow the parent promise, then allocate/copy, then drop the original buffers, and only then finish their original holdings. This deliberately costs a real transient copy; it avoids both prohibited accounting aliases/early release and a permanent holding record per corpus document without adding a Core merge API. Removing this handoff would either strand document holdings or release live data. Snapshot allocation is declared last, after all actual records/vectors.

The old root M3 callback-host/account bridge was removed after the actual M3 account-backed APIs became available. Raw compatibility APIs without a parent lifetime conservatively retain their charges, as documented by M3; they are not the final lifetime-bearing CLI/MCP binding. Existing hostile-format ceilings are unchanged.

The standalone kernel executable admits an actual parent and one exact owned pure-kernel worker. It verifies native PID/start/group facts, observes full RSS and native wait4 peak RSS, handles cancellation/collection before release, and binds child death to the native parent. A short missing-observation window retains the entire promise and requires real terminal peak evidence or typed refusal; it never substitutes zero usage. No blanket RLIMIT_AS is installed on Linux or macOS. Historical AS/EINVAL, 48 MiB allocation and 512 MiB stress facts remain intact. This is not a descendant-processing-executor proof.

## Native Service

`omni_service::{authority,runtime}` uses the unchanged version-one command catalog. Only native Owner/Selection/Session/Permit capabilities grant authority; DTO identifiers, paths, hashes, booleans, transport labels and approval claims cannot. Approval is separate, exact, current-revision-bound and one-use. Resolution, effects and delivery recheck current policy; HTTP observations are actual unmodified native facts.

Root `NativeLibraryService` implements real selected-library browse, versions, confined range reads, kernel queries, truthful observations and exposure. Owner adapters attach through `bind_domains`; unbound operations refuse rather than invent success, empty mounts, initialized history or model readiness. `Delivery` owns frame resources and rechecks before encoding and every controllable transport write. Oversized encoded responses produce a bounded typed failure. Optional status budget fields preserve old response bytes when absent.

## Gates And Remaining Boundary

Builder gates cover actual root kernel consumption (including corrupted native CURRENT), cache/reader lifetime, versioned native source operations, human approval/revocation, legacy public retrieval/model behavior, native kernel regressions, all seven prototype faces and an actual live owned-worker RSS refusal. Exact private commands/outputs are retained outside the repo. Shared-account opaque fixture suites run serially; the earlier parallel contention failure is preserved, not relabeled as success.

The full root run is **not green**: 115 cases pass, but 11 status cases fail because the untouched status probe still requires the retired Tantivy layout. A narrow status/test integration lease is requested outside the repo; those failures are preserved rather than omitted or repaired with a fake old index. The kernel/service/processing scoped suite, seven prototype faces, real RSS case, format and strict Clippy gates pass.

This is a landed integration slice, not full M4/M6 or B3/B4 acceptance. Remaining obligations include the status integration, generic admitted byte providers, archive Directory composition, streaming orchestration/disk vectors, complete M1/M2/M5 host composition, actual daemon/CLI/MCP Delivery-preserving activation, queued-claim funding/returned-output lifetime and descendant-executor admission repair, the single consequential authority/admission review, and native macOS execution. No agent, model download, push or private configuration change is required by this landing.
