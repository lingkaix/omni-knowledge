# Effective Process Resource Admission

## Accepted Owner And Scope

[Storage](../specs/storage.md#effective-resource-accounting) and [service](../specs/service.md#encoding-and-compatibility) own the accepted startup defaults, accounting lifetimes and status obligations.
The supervisor-approved sequencing permits this seam before M0 acceptance without changing M0 criteria or the separate durable-authority gate.
The earlier jobs record's pending-policy description is historical; these owners now decide the policy.
This change activates no Root, transport, processor, mount, cache publication or authorization caller.

## Implementation Plan

Resolve half of actual startup physical RAM, an optional explicit memory override, and selected-volume available bytes minus max(2 GiB, ceil(capacity/20)).
Expose explicit storage override as a further ceiling, never permission to spend the required free-space floor.
Use fixed-size Linux kernel observations and descriptor-relative volume observations; use an already-locked safe native binding for macOS physical RAM.
Own one process-lifetime queue account; reject reinitialization and inherited-process use instead of resetting it per library.
Standalone Queue constructors remain scoped cooperative fixtures, not alternate process caps.

Keep the jobs public types, signatures, retained intent, ordering and ordinary transitions unchanged.
Extend only private accounting so job claims and pre-verification/runtime/resource holdings share the existing reserved counter and mutex.
Use explicit finite record capacity, a checked shared lifetime sequence and typed too-large versus currently-waiting results.
Provide atomic claim-to-resource splitting, growth before allocation, and explicit actual settlement without release on capability drop.
A split resource can outlive worker settlement without retaining the mount execution slot.
Charge remaining unwritten storage promises; after actual same-volume writes, reconcile their consumed portion with fresh native free-space facts so written bytes are not charged twice.
No release implies physical deletion, termination, generation retirement or permission.

## Necessity And Reasoned Ablation

Without native observations, accepted defaults would be guessed values rather than effective facts.
Without process ownership and the same queue counter, per-library resets or parallel controllers could admit more than the effective budget.
Without holdings independent of mount execution, either live children/pins lose charges on worker completion or completed workers keep execution slots forever.
Without explicit splitting, an existing complete claim would need a double charge or an uncharged transfer interval.
Without distinguishing whole-limit impossibility from current contention, work would either fail incorrectly or wait forever for an impossible need.
Without write reconciliation, physical free-space reduction and the original unwritten promise would count the same generated bytes twice.
A bounded native table is sufficient; no resource crate, processor catalog, callback registry, executor, event history or speculative recovery is necessary.
These are structural necessity claims, not uncertain performance claims requiring removal experiments.

## Remaining Actual-Caller Contracts

Startup must select an already admitted private cache directory, sample once and pass the actual accepted configuration before any job-caused allocation.
Direct library hosts and future service adapters must obtain this same process owner, never create a replacement pool.
Executors must reserve complete concurrent costs before allocation/growth, use the visible waiting result without spinning, and retain capabilities until children are reaped and runtimes/models/readers actually cease using memory.
Only trusted real settlement can release a holding; losing a capability intentionally strands its charge.
Writers must reserve before writing, report only actual writes on the selected volume, and retain unconsumed promises through unknown child/I/O outcomes.
Native free-space observations are not filesystem quotas, opaque-parser enforcement, power-loss proof or worker-stop evidence.
Status/MCP mapping must expose effective configuration, current observations, total charges and waiting reasons without inventing current DTO fields.
Current exposure, source/residency verification, immutable fingerprint construction, persistent operation recovery and actual cache lifecycle remain separately gated.
Existing hostile-format ceilings and M0 obligations are unchanged.

## Verification Boundary

Focused locked/offline Core checks and the unchanged existing regression pool protect composition, not independent acceptance of this new mechanism.
Producer public-interface observations will use actual native facts, private owned fixtures and actual reservation/resource/thread lifetimes.
Permanent independent jobs/admission tests and consequential review remain external; this producer does not inspect their oracle or records.
Linux observations do not qualify macOS behavior; the available target toolchain limits compilation evidence and must be reported explicitly.
