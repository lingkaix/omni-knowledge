# Explicit Existing Git Or Separate History

The [compiled History seam](../../crates/knowledge-history/README.md) now offers actual `use_existing(ExistingRepository, home, text_root, owner, claim)` alongside the unchanged separate `init` choice. This is not automatic repository discovery, relocation, branch management, a stored-path grant or package/model authorization. Native M6 must supply current ownership/permission and actual non-synchronized placement on selection and every later open. Unknown/synchronized observations refuse before app effects.

Use-existing uses the actual selected user Git object database and app ref namespace, and a private index outside synchronized storage. Initial app ancestry is the selected qualified user branch, verified in the same native transaction as app-ref creation. User HEAD/branches/index/staged bytes remain untouched; original authors/signatures and unchanged tracked media/attributes/gitlinks remain. New app commits are selected regular UTF-8 text deltas only, with existing executable text mode retained. No media is deleted to enforce a newly empty text-only tree, and no absolute .git redirect is introduced in the home. The separate path creates independent external local app history without changing user Git.

Selected user configuration is parsed by native Git's no-includes, stdin, name-only mode, with global/system configuration disabled and no copy of potentially credential-bearing values written to app metadata. Unsafe includes, rewrite/transport widening, alternates and linked-worktree configuration refuse. Native plumbing keeps hooks/fsmonitor/filters/diff execution inert; user configuration is never overwritten. Exact config version drift refuses until explicit native re-selection. Re-selection validates new inert configuration without resetting the current app history to user HEAD. Native directory/control-file symlinks do not redirect app binding reads.

Three real public-operation controls prove: retained original ancestry/media and byte-identical unrelated staged index/branches/config with hostile hook/filter/fsmonitor/textconv definitions unexecuted; synchronized/unknown placement refusal and actual separate history without home Git redirection; and an include target that is a real owned FIFO never opened by the no-includes parser. The placement-value refusal is a boundary control, not a claim to qualify a real cloud provider. Git-only publication still does not install home bytes or mean saved_local; M1 owns safe file installation/journals.

All earlier protected Git and native signing/bundle/lifetime cases remain unchanged. Initial user-repository fixture setup failure (driver lacked an explicit selected working tree) is retained and corrected in the owned fixture only; no real Git is substituted and no assertion/budget is weakened. Native macOS/provider qualification and independent consequential review remain required. Actual remote/schedule completion remains active, not a waived contract item or a claim from these adoption controls.
