# Native scopes from one actual claim

## Necessity and boundary

A full-corpus native producer/query cannot keep every temporary source/version FD in one
transport frame's result-check list. Nor may each next source borrow new global credit
while the actual job already owns its complete envelope. Existing command mediation,
selection, policy, Core accounting and source checks remain the only implementations.
This change is a scoped SDK prerequisite, **not whole-application M4/M6 activation**.

`Permit::fork_processing_scope` accepts only an actual admitted Process, Refresh or Query.
It shares the EXACT immutable command and native session/selection revisions; metadata
status is refused. A holding/ID/DTO never grants intention or exposure. The host must still
retain/check its actual job and generation/input cause. The scope starts fresh IO rather
than inheriting a different source's old result/version pins.

Before copying scope state, Core splits the complete requested envelope from the actual
live Claim and full expected key. A bounded local spend counter only restricts that loan;
it cannot enlarge/refund credit, fall back to global reserve, or give clones another loan.
The original command's real budget survives with shared command bytes, independently of
old result pins. Ordinary transport frame admission and its original ceilings are unchanged.

`rejoin_processing_scope` is consuming and requires exclusive ownership. Native FD/check
payloads, callback-vector storage, session/revision copies and scope fields die before
returning the actual loan to that exact original live Claim. A borrowed scope is returned
as an owning typed refusal, not force-released. After fully destroyed payloads, a refused
rejoin finishes the actual holding; no work/payload is put in static quarantine.
Winning scopes/pins remain owned through final delivery; nonwinners can be retired/rejoined.
This uses existing Core split/rejoin, not a second resource or scheduling engine.

## Executed controls and retained REDs

The isolated fixture owns ONE actual process account and actual owner-selected files.
A real admitted Process frame is the actual input of its queued/claimed job. It drains
ALL free account credit, spends from the same claim, rejects clone respending, and proves
that old result FDs end independently while shared command bytes retain their real credit.
Thirty-two sequential native FD scopes rejoin under zero global free credit with one
8 MiB claim, exceeding that claim divided by the 1 MiB live scope without a corpus cap.
A live clone prevents rejoin; every actual pin dies before the credit is returned.

Independent ablations actually fail: ordinary late growth returns Busy under full pressure;
omitting the shared command sponsor frees 67,108,864 bytes while the child still uses it;
global release instead of exact rejoin exposes a forbidden free-credit gap. Restored cases pass.
Initial missing-Arc and numeric job-ID compile REDs are retained. The first wrapper used an
incorrect exact-test prefix, so its child ran ZERO tests: test-2 and the first growth ablation
are NONDECIDING and are not qualification. The corrected wrapper requires actual child test
execution; deciding test-3/test-5 and the suffixed growth ablation execute the real fixture.

A parallel Root library run exposed its old global exact-credit oracle racing other native
tests (25,101,113,380 versus 25,108,979,096 available). The unchanged extraction/settlement
body passes alone; its wrapper now owns that global-account premise in an actual collected
child. The identical parallel affected run then passes, without relaxing any assertion.

`sha2` is a test-only dependency edge for real admitted-input/code digests, not a new package,
processor or authority. Native physical RSS, full-corpus publication/query, loaded model
quality and whole-product Linux/macOS acceptance remain separate obligations.
