## Actual Mechanism

watch and monitor now share one FSEvents owner instead of a Linux-only watch plus a separate notify MacWatch implementation.
After SAME-account prepayment, the owner starts one trusted packaged omni-fsevents child with the held selected directory as stdin.
The child uses F_GETPATH_NOFIRMLINK and the native mount point to construct the slash-free device-relative stream path, including APFS Data-volume paths.
The real C callback reduces native flags and IDs into fixed 56-byte nonblocking frames, with bounded path/exclusion inspection and no callback-time Rust allocation.
The current parent read policy/root is checked before delivery; captured exclusions cannot suppress root/drop/wrap/loss flags.
Native volume UUID drift, malformed or truncated transport, drops/coalescing/must-scan/root change, work exhaustion and finite lease expiry require bounded reconciliation and stream rebuild.
Neither quiet nor acknowledgement repairs lost coverage or grants source reads, identity, hydration, pruning, or absence.

Core Foundation internal allocations cannot honestly be bounded by the callback buffer in the parent.
The helper therefore reuses knowledge-processing's existing native resident-set observer under the original parent Account reservation, with separate parent overhead and child RSS allowances.
This adds a macOS-only dependency edge to an existing Apache-2.0 crate, not new registry packages, another pool, or another executor.
RSS sampling has allocation/syscall overshoot limits; it is not a hard physical-memory cap.
The helper samples between finite runloop calls and enforces its own finite lease and aggregate callback-work limit when the parent stops polling.
Native objects, callback context and the root FD remain allocated until process exit.
Only the exact parent's confirmed child exit, closed transport, and destroyed owned metadata permit settlement; bounded unknown stop retains exact handles and charge.
The existing processing settle helper is not used because it hides wait failure and has no bounded unknown outcome.

Store::reconcile_watched performs the existing actual bounded enumeration and known-descendant inspection on the exact watch-owned mount.
Only a complete durable inventory checkpoint at unchanged hint epoch/current scope can be followed by its pre-scan EventCursor record.
The cursor binds backend/library/mount, held root, native volume UUID, read scope and scan; it is not an access grant.
Restart deliberately uses a new stream and full bounded catch-up rather than trusting a retained event ID or claiming durable replay.
The compiled RustDoc shows the actual generic consumer API without editing separately owned startup, packaging or service callers.
